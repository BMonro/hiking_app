2|4.1.	Реалізація серверної частини
3|Серверну частину застосунку розгорнуто на хмарній платформі Supabase [12] без використання окремого VPS-сервера. База даних PostgreSQL [13] містить 15 таблиць та одне представлення profile_stats з увімкненим механізмом Row Level Security [16]. Автентифікацію реалізовано через Supabase Auth із підтримкою входу через email і пароль та Google OAuth. Серверна логіка, що потребує захищеного доступу до зовнішніх API або атомарного виконання операцій, реалізована через 10 Edge Functions на базі Deno, які відіграють роль BFF-шару між мобільним клієнтом і зовнішніми постачальниками даних.

9|const dLat = ((b.lat - a.lat) * Math.PI) / 180;
10|const dLon = ((b.lon - a.lon) * Math.PI) / 180;
11|const lat1 = (a.lat * Math.PI) / 180;
12|const lat2 = (b.lat * Math.PI) / 180;
13|const x = Math.sin(dLat/2)**2 + Math.cos(lat1)*Math.cos(lat2)*Math.sin(dLon/2)**2;
14|return 2 * R * Math.asin(Math.sqrt(x));
15|}

143|4.2.2.	Реалізація маршрутів, геопошуку та збереження
144|Каталог публічних маршрутів завантажується через RoutesRepository з динамічним формуванням запиту до PostgREST залежно від встановлених фільтрів. 146|4.3.	Реалізація навігації та офлайн-режиму
